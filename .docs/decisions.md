# Project decisions

Running list of lasting decisions, in chronological order. Only append to the end; see the `log-prompts` skill for the format.

- **2026-10-13** — Every prompt and every decision is logged in `.docs/` by the `log-prompts` skill (named `registrar-prompts` at the time). Keeps a history of what was asked and why each choice was made. ([prompt](prompts/2026-10-13.md), entry 1)
- **2026-10-13** — Documentation and logs in `.docs/` are written in Portuguese. The user's working language. ([prompt](prompts/2026-10-13.md), entry 1) (superseded on 2026-10-13)
- **2026-10-13** — Logging is enforced by hooks in `.claude/settings.json`: `UserPromptSubmit` records the prompt and `Stop` keeps the turn from ending with a pending entry. The instruction in `CLAUDE.md` alone could be forgotten. (log entry since removed) (superseded on 2026-10-13)
- **2026-10-13** — Commits follow Conventional Commits, with the description in Portuguese. Requested by the user; the language was chosen for consistency with the documentation. (log entry since removed) (superseded on 2026-10-13)
- **2026-10-13** — The project languages are HTML, CSS and JavaScript. Defined by the user; frameworks, libraries and build are not decided yet. ([prompt](prompts/2026-10-13.md), entry 2)
- **2026-10-13** — Logging relies only on the `log-prompts` skill and the instruction in `CLAUDE.md`, with no hooks. The hook script and `.claude/settings.json` were removed from the repository. ([prompt](prompts/2026-10-13.md), entry 3)
- **2026-10-13** — All documentation is written in English, including `.docs/`; prompt quotes stay verbatim in the language they were written in. Requested by the user. ([prompt](prompts/2026-10-13.md), entry 3)
- **2026-10-13** — Commit messages start with a type (`feat`, `fix`, `chore`, `docs`, `refactor`…) and never carry a scope in parentheses; commits are small, never mix unrelated changes, carry no Co-Authored-By line and are not pushed without prior authorization. Rules given by the user; see the `commit` skill. ([prompt](prompts/2026-10-13.md), entry 3)
- **2026-10-14** — The project is Chess Life: a personal chess website with public pages (story, gallery, sign-up, login), a restricted dashboard of recorded games with Chart.js charts, and a complementary game against an AI. Defined by the user's academic specification; see `docs/project.md`. ([prompt](prompts/2026-10-14.md), entry 2)
- **2026-10-14** — Stack: HTML/CSS/JS front-end, Node.js + Express REST API that also serves the static files, MySQL on a Linux VM, bcrypt for passwords, Chart.js for charts; chess.js plus Gemini and/or Stockfish for the AI module. Set by the specification. ([prompt](prompts/2026-10-14.md), entry 2)
- **2026-10-14** — Project documentation lives in `docs/`, with `docs/project.md` as the full specification; `.claude/CLAUDE.md` only gives a short overview pointing to it. Requested by the user. ([prompt](prompts/2026-10-14.md), entry 2)
- **2026-10-14** — The application lives in `site-pessoal/`, built on SPTech's web-data-viz template: its back-end (`app.js`, `src/`) is reused and adapted, and its front-end was rebuilt in the "classic" design (cream, green and brass; Playfair Display and Source Sans 3). Chosen by the user. ([prompt](prompts/2026-10-14.md), entry 4)
- **2026-10-14** — Changes to the APIs (`site-pessoal/src/`, `app.js`) and to existing front-end pages need the user's approval first. Requested by the user. ([prompt](prompts/2026-10-14.md), entry 4)
- **2026-10-14** — Documentation lives in `.docs/` (`project.md`, `site-pessoal.md`), not in `docs/`. Requested by the user. ([prompt](prompts/2026-10-14.md), entry 4)
- **2026-10-14** — `site-pessoal/public/` has one folder per feature plus `shared/` for the style, session and layout code. File names and identifiers are in English; UI copy is in Portuguese. Follows the review checklist and the language convention. ([prompt](prompts/2026-10-14.md), entry 4)
- **2026-10-14** — Chart.js 4.4.1 is loaded from the cdnjs CDN. No build step is needed. ([prompt](prompts/2026-10-14.md), entry 4)
- **2026-10-14** — Only system fonts are used (no web fonts): `--font-heading` (Georgia) and `--font-body` (Segoe UI or the system font) in `shared/style.css`. Requested by the user. ([prompt](prompts/2026-10-14.md), entry 5)
- **2026-10-14** — Every front-end API call goes through `apiRequest()` in `shared/api.js`, which turns each HTTP status into a standard Portuguese message (overridable per call) and never shows server text to the user. Requested by the user. ([prompt](prompts/2026-10-14.md), entry 5) (superseded on 2026-10-14)
- **2026-10-14** — The API standardization (`shared/api.js`, `apiRequest()`) was reverted: pages call `fetch` directly again, each with its own error messages. The user found it too complex. ([prompt](prompts/2026-10-14.md), entry 6)
- **2026-10-14** — Changes are no longer committed automatically after each task; commits happen only when the user asks, through the `commit` skill. Requested by the user. ([prompt](prompts/2026-10-14.md), entry 6)
- **2026-10-14** — CSS must be well structured (tokens and base styles in `shared/style.css`, feature styles in their folder, rules grouped by section, media queries at the end), avoid unnecessary repetition (reuse the `:root` variables and shared classes) and stay as simple as possible. Requested by the user; see "CSS Rules" in `.claude/CLAUDE.md`. ([prompt](prompts/2026-10-14.md), entry 7)
- **2026-10-14** — Code must be simple and easy to understand, with low cognitive complexity: direct solutions, shallow nesting, small single-purpose functions and no abstractions for one or two uses. Requested by the user; see "Simplicity Rules" in `.claude/CLAUDE.md`. ([prompt](prompts/2026-10-14.md), entry 8)
- **2026-10-14** — Naming and documentation follow Clean Code: names reveal intent, comments explain why, and shared or non-obvious functions get a short doc comment. Requested by the user; see "Clean Code Documentation Rules" in `.claude/CLAUDE.md`. ([prompt](prompts/2026-10-14.md), entry 8)
- **2026-10-15** — The dashboard ("Meu desempenho no xadrez") shows only games played on the site; there is no manual game form. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 2)
- **2026-10-15** — The `partida` table stores result, opponent, color, moves in SAN, opening and a DATETIME set by the database; the API identifies the opening from the moves with an opening list in `src/models/openingBook.js` (longest matching sequence). Requested by the user; the list avoids external services and new dependencies. ([prompt](prompts/2026-10-15.md), entry 2) (superseded on 2026-10-15)
- **2026-10-15** — New back-end code uses parameterized queries through `database.executar(sql, parametros)`. Fixes the SQL injection found in the legacy models. ([prompt](prompts/2026-10-15.md), entry 2)
- **2026-10-15** — Dashboard KPIs: games today vs. yesterday, total win rate vs. until yesterday, and favorite opening; charts: games per week by result, results and openings. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 2)
- **2026-10-15** — The site logo is the "Emblema do Rei" (a cream king in a green seal with a brass ring) in `shared/logo.svg`, shown before the "Chess Life" text in the header and used as the favicon. Chosen by the user from three proposals. ([prompt](prompts/2026-10-15.md), entry 3)
- **2026-10-15** — The database is modeled and implemented in MySQL 8.0+, and the model is documented in `.docs/database.md`, which changes first whenever the model changes. Requested by the user; 8.0.16+ enforces `CHECK` constraints. ([prompt](prompts/2026-10-15.md), entry 5)
- **2026-10-15** — Preliminary model: `usuario` (adapted from the legacy table, with `senha_hash`), `abertura` (known openings, `lances` unique) and `partida` (with `fk_usuario` and `fk_abertura`). Legacy `empresa`, `aviso`, `aquario` and `medida` are dropped, and gallery photos have no table. Choices made by the user. ([prompt](prompts/2026-10-15.md), entry 5)
- **2026-10-15** — The repository `README.md` is written in Portuguese and illustrated with animated SVGs in `assets/`, in the site palette. Requested by the user, based on a reference README. ([prompt](prompts/2026-10-15.md), entry 6)
- **2026-10-15** — Reference documents in `.docs/` are numbered in reading order (`01-project.md`, `02-site-pessoal.md`, `03-database.md`), with numbered main sections, and `.docs/README.md` indexes them; the logs (`decisions.md`, `prompts/`) are not numbered. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 6)
- **2026-10-15** — The data model shows all four relationship kinds: `perfil` (1:1 with `usuario`, identifying, FK as PK) and `lance` (weak entity of `partida`, PK `(fk_partida, numero)`, `ON DELETE CASCADE`) join the existing non-identifying 1:N relationships. `partida.lances` (TEXT) is replaced by `lance`. Requested by the user; the user chose replacement over duplication. ([prompt](prompts/2026-10-15.md), entry 8)
- **2026-10-15** — Chess rules are the project's own JavaScript (`public/play/rules.js`), with the board as an 8×8 matrix of `{ color, type }`, instead of chess.js. A move is legal when it leaves its own king unattacked. Draws by rule (threefold repetition, fifty moves, insufficient material) end the game automatically. Requested by the user (matrix, every rule); no new dependency. ([prompt](prompts/2026-10-15.md), entry 10)
- **2026-10-15** — The game page (`/play/play.html`, "Jogar" in the menu) is a local game between two people. It saves the finished game through the existing `POST /partidas/cadastrar` with SAN moves, from the logged-in user's side. Requested by the user; the server API stays unchanged for now. ([prompt](prompts/2026-10-15.md), entry 10)
- **2026-10-15** — The physical model is implemented by `site-pessoal/src/database/01-schema.sql` (database and tables) and `02-seed.sql` (openings). Both can be rerun without losing data, and constraints are named `uq_`/`fk_`/`chk_`/`idx_`. The legacy `script-tabelas.sql` stays until the API code is adapted. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 11)
- **2026-10-15** — The site has a light and a dark theme. The header button switches them, the choice is saved in `localStorage`, and the default is the system theme. `shared/theme.js` sets `data-theme` in every page's `<head>`, and the dark palette is one `:root[data-theme="dark"]` block. Colors are split by role (`--green` surfaces, `--green-text` text, `--light-ink`/`--dark-ink` fixed). Requested by the user. ([prompt](prompts/2026-10-15.md), entry 12)
- **2026-10-15** — The API contracts are documented in `.docs/04-api.md`, which changes first when a route changes. Errors are plain Portuguese text that pages show as is, and successful replies are JSON. The legacy request field names stay for compatibility. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 13)
- **2026-10-15** — The back-end was rebuilt from the template's code. The unused legacy resources (`aviso`, `aquario`, `medida`, `empresa`, `routes/index.js`) were deleted. It has one `mysql2` connection pool with `query` and `transaction`, async controllers, English identifiers, and bcrypt hashes through `bcryptjs`. A game and its moves are saved in one transaction, and openings come from the `abertura` table. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 13)
- **2026-10-15** — `perfil` has its own `id`, and `UNIQUE (fk_usuario)` keeps it 1:1 with `usuario`, now a non-identifying relationship (`partida` → `lance` stays the identifying one). The schema relies on MySQL 8's defaults (`utf8mb4`, InnoDB). The user's schema edit, with the 1:1 kept. ([prompt](prompts/2026-10-15.md), entry 15)
- **2026-10-15** — The API connects to MySQL as `chess_life_user_db`@`localhost`, created by `site-pessoal/src/database/03-app-user.sql` with least privilege per table: `SELECT`/`INSERT` on `usuario`, `SELECT` on `abertura`, `SELECT`/`INSERT`/`DELETE` on `partida` and `lance`, nothing on `perfil`. Its password comes from the `@senha_app` session variable and is never written in a versioned file. Requested by the user; the repository is public. ([prompt](prompts/2026-10-15.md), entry 17) (superseded on 2026-10-15)
- **2026-10-15** — `03-app-user.sql` writes the application user's password (`Urubu100`) in the script, by the user's choice. It is public with the repository and only for local development; the VM's user gets another password with `ALTER USER`. Supersedes the entry 17 rule that the password comes from `@senha_app`. ([prompt](prompts/2026-10-15.md), entry 18)
- **2026-10-15** — The dashboard is titled "Desempenho no Xadrez" and, on screens wider than 800px, fits the window without page scroll; only the games table scrolls inside its panel. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 19)
- **2026-10-15** — The game page also fits the window without page scroll on screens wider than 800px, with the footer hidden; the board is sized with container query units. Requested by the user. ([prompt](prompts/2026-10-15.md), entry 23)
