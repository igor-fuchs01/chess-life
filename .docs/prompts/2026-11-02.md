# Prompts — 2026-11-02

## 1. Replace the header with the glass sidebar

**Prompt:**

> Eu quero que você implemente a glass-sidebar que está no repositório .temp nesse projeto substituindo o header, traga todas as funcionalidades presentes nela e deixe o código mais simples possível, só adapte as opções dentro da sidebar para as opções de navegação do projeto, juntamente com a estilização adequada para o projeto.

**What was done:** The header was replaced by a floating glass sidebar adapted from `.temp/glass-sidebar`: `shared/layout.js` now has `renderSidebar()` (logo, the existing navigation links with icons, theme button and "Sair" at the bottom), its styles replace the header styles in `shared/style.css`, and the six pages use `<aside id="site-sidebar">` instead of `<header id="site-header">`. The game board width on phones now subtracts the sidebar space, stale "header" comments in the page stylesheets were updated, and `.docs/02-site-pessoal.md` documents the sidebar. It could not be checked in a browser because the Chrome extension was not connected; `layout.js` passed a syntax check.

**Decisions:**

- Kept every feature of the glass sidebar (icon rail, opening over the page on hover with animated width and labels, glass background with `backdrop-filter`, active item, danger hover on "Sair", `:focus-visible` outline, bottom group, `title` on items) — requested by the user.
- Added `:focus-within` so the bar also opens with Tab — the original demo promised keyboard opening but its CSS only opened on hover.
- Class names simplified from BEM (`glass-sidebar__item`) to the project's style (`sidebar-item`, `active`, `danger`) and the CSS lives in `shared/style.css`, not a new file — follows the project's patterns and file rules.
- Glass colors come from the existing tokens (`color-mix` of `--card`, `--green`, `--brass`, `--danger`, `--shadow`), so the dark theme needs only one new token (`--glass-border`) instead of a copy of the original's color block — less repetition, matches the site design.
- `body` reserves the space for the closed bar instead of a `glass-sidebar-page` class — every page has the sidebar.
- Added `overflow: hidden` and adjusted item padding (10px) so the icons fit the 46px inner rail and invisible labels do not open the bar when hovered beside it.
- Icons: ⌂ Minha história, ▣ Galeria, ♞ Jogar, ▤ Dashboard, ➜ Entrar, ☾/☀ theme, ⏻ Sair — plain text symbols, like the original, with no icon library.

## 2. Chess icons, full-width sections and the sidebar hover color

**Prompt:**

> Mude os icones referentes as páginas deixando mais temático para o projeto, além disso, as seções devem ocupar a lateral esquerda e não deve existir um espaço exclusivo para a barra lateral, no entanto o conteudo dentro das seçoes precisam readaptar(recentralizando)

**What was done:** The sidebar page icons are now chess pieces (`shared/layout.js`). `body` no longer reserves a strip for the sidebar: sections and the footer span the whole window under it, while `.wrap` adds `--sidebar-space` to its left padding and max-width, so the content is centered in the space right of the closed bar (`shared/style.css`, plus `.auth`, `.dash .wrap`, `.play .wrap` and `.hero` in their feature stylesheets). The item hover is now a green tint instead of a cream tone. `.docs/02-site-pessoal.md` was updated. It was not checked in a browser (the Chrome extension was not connected).

**Decisions:**

- Icons: ♚ Minha história (the author's story), ♝ Galeria, ♞ Jogar, ♜ Dashboard, ♟ Entrar; filled pieces, since outlined ones look thin at 20px; `\uFE0E` after the pawn so it does not show as a color emoji. Theme (☾/☀) and Sair (⏻) were kept, since they are actions, not pages.
- Content is shifted through `.wrap`'s left padding (and its max-width grows by the same amount, so the content width stays the same) instead of padding each section — one shared rule covers every page, and section backgrounds still reach the left edge.
- Hover: 14% tint of `--green-text` with green text, without the white border — the previous `--card` tone and white border barely showed over the light cream; `--green-text` is light green in the dark theme, so it works in both. The item border was removed and its padding grew 1px to keep the icons aligned with the logo.

## 3. Check password strength only on sign-up

**Prompt:**

> A validação de senha não pode acontecer no login somente no register

> A ideia é que realmente autentique, no entanto, havia um senha no meu banco de dados cadastrada como 12345678 para um usuário X, e ele não consegue acessar a página porque está sendo barrada a entrada dele no próprio login

**What was done:** Login no longer checks password strength: the check was removed from `auth/login.js` (and `password.js` is no longer loaded by `login.html`) and from `authenticateUser` in `src/controllers/usuarioController.js`, which now only compares the e-mail and password with the database. Sign-up keeps the check on the page and in the API. `04-api.md` and `02-site-pessoal.md` were updated.

**Decisions:**

- The strength check was removed from the API's login too, not only from the page — the user's goal is that a user whose password was saved before RN02 (such as `12345678`) can log in, and the API was what rejected them. Asked first, as the project rules require for API changes.
- RN02 applies when a password is created (sign-up); login only authenticates.

## 8. Keep "Agradecimentos" highlighted while its section is on screen

> Ao clicar em agradecimentos e estar na seção, é necessário que fique hover

**What was done:** On the home page, `highlightVisibleSections()` in `shared/layout.js` watches the thanks section with an `IntersectionObserver` and gives the "Agradecimentos" link the `in-view` class while at least half of the section is on screen; `shared/style.css` gives `in-view` the same look as hover. `02-site-pessoal.md` was updated. ## 9. Highlight "Agradecimentos" with CSS instead of an observer

**Prompt:**

> Eu não quero necessariamente utilizar um observe para fazer isso, não existe algo mais simples?

**What was done:** The `IntersectionObserver` of entry 8 was removed from `shared/layout.js`. The highlight is now CSS only, in `shared/style.css`: `body:has(#agradecimentos:target) .sidebar-item[href="#agradecimentos"]` shares the hover rule, so the link keeps the hover look while the address ends in `#agradecimentos`. `02-site-pessoal.md` was updated. Not checked in a browser.

**Decisions:**

- `:target` with `:has()` instead of JavaScript — the simplest option, and the user's choice against the observer.
- Accepted trade-off: the highlight follows the click (the address), not scrolling, so it stays until the address changes even if the user scrolls away.
