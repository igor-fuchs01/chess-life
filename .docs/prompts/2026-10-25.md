# Prompts — 2026-10-25

## 1. Remove bcrypt and store plain-text passwords

**Prompt:**

> Eu quero que você remova o bcrypt desse projeto, as senhas não terão hash e serão armazenadas diretamente no banco de dados

**What was done:** Removed `bcryptjs` (`npm uninstall`) and its use in `usuarioController.js`: sign-up saves the password as is and login compares it with `user.senha`. `usuarioModel.js` and `01-schema.sql` now use `senha VARCHAR(100)` instead of `senha_hash CHAR(60)`. Updated `01-project.md`, `02-site-pessoal.md`, `03-database.md`, `04-api.md`, `README.md` and `CLAUDE.md`. Existing local databases were not migrated: `03-database.md` section 8 has the `ALTER TABLE` to run.

**Decisions:**

- Plain-text passwords, no hashing — the user's choice; they were told anyone who can read the table sees every password.
- The column is renamed to `senha`, since it no longer holds a hash. Discarded: keeping `senha_hash`, a misleading name.
- `VARCHAR(100)` with a new API check `A senha pode ter no máximo 100 caracteres.`, following the name and e-mail length checks, so a long password gets a `400` instead of a MySQL error (`500`).
- The front-end and the request and reply contracts did not change.

## 3. Libraries needed for express-session

**Prompt:**

> se eu usar o express session, eu vou precisar adicionar mais bibliotecas?

**What was done:** Answered the question without changing code. `express-session` is a new dependency itself; it handles the session cookie without `cookie-parser`, the secret goes in `.env` through `dotenv`, and the same-origin setup needs no CORS changes. The default `MemoryStore` is enough for the academic VM but loses sessions on restart; `express-mysql-session` would persist them in MySQL. Compared with JWT, both need one library, and the session is simpler for a site served by Express.

**Decisions:**

- None.

## 5. Replace CSS grid with flexbox

**Prompt:**

> refatore o css, evite utilizar grid, prefira utilizar display flex

**What was done:** Replaced every `display: grid` in `site-pessoal/public/` with flexbox: the chess board (`shared/style.css`), the home hero and feature cards, the gallery photos, the story inspirations, the dashboard panels and indicators, and the game page layout, move list and action buttons. `dashboard.html` got two `.panel-row` wrappers and a `wide` class on the larger panels. Checked in headless Chrome at 1280×800 and 390×844 against the old version: phone layouts, the game page, gallery and story are identical; on the home hero and the dashboard, the wide side is about 10px narrower than before, because flex counts the board border and panel padding before sharing the space. No horizontal overflow, and the dashboard and game page still fit the window. Documented the rule in `.claude/CLAUDE.md`, `02-site-pessoal.md` and `01-project.md`.

**Decisions:**

- Flexbox instead of grid in all CSS — the user's choice.
- The dashboard's 2×2 area needed row wrappers in `dashboard.html`: a single wrapping flex container would share the free height with the indicators row too. Discarded: fixed heights computed with `calc`.
- Board squares and gallery photos get a percentage width with `aspect-ratio: 1` inside a wrapping container, instead of percentage heights.
- The small width change on the home hero and dashboard was kept; matching it exactly would need hard-coded `calc` widths.
- Found, not fixed: on the game page, the "Tentar salvar de novo" button shows even with `hidden`, because `.btn` sets `display`. It was already like this before the refactor.
