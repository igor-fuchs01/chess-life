## 5. System fonts and standard API calls

**Prompt:**

> eu quero que você remova essas fontes da google e utilize somente fontes que já estejam presente no html, além disso eu quero que você padronize as chamadas de API juntamente com os possíveis erros

**What was done:** removed the Google Fonts links from every page. Headings and text now use system fonts (Georgia, and Segoe UI or the system font) through the new `--font-heading` and `--font-body` variables in `shared/style.css`; the Chart.js font reads `--font-body`. Created `shared/api.js` with `apiRequest()` and `ApiError`; login, sign-up and the dashboard now call the API only through it. Tested against `app.js` with the local database: 400, 404, a 404 with a custom message, 403 and a network failure each produced the expected message. Documented in `.docs/site-pessoal.md`. `src/` was not touched.

**Decisions:**

- System font stacks instead of web fonts — requested by the user. Georgia keeps the serif look of the classic design and comes with Windows and macOS.
- Fonts are variables in `:root`, next to the colors — one place to change the design.
- API standardization was done on the front-end only — the user asked to be asked before any change to `src/`. The statuses the adapted API should reply with are listed in `.docs/site-pessoal.md`.
- Error messages are chosen by HTTP status, with an optional override per call, and text sent by the server is never shown — the legacy API replies with technical texts ("Seu email está undefined!") and raw `sqlMessage`, which must not reach the user.
- `dashboard/dashboard.css` was committed together with the user's own reformatting of that file, because the whole file had been reformatted and the font change could not be split from it.
