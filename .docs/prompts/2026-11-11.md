# Prompts — 2026-11-11

## 1. Show a wrong exercise move in red

**Prompt:**

> Dentro do game.js altere a coloração para vermelho quando o usuário errar o exercício para que fique aparente o erro dele!

**What was done:** After a wrong move, the move's two squares on the board are drawn in red (`wrong-move` class instead of `last-move`) and the status "Lance errado. Tente de novo." turns red. Changed `site-pessoal/public/play/game.js`, `play/game.css` and added the `--square-wrong` token to `shared/style.css`; the board layout paragraph in `.docs/02-site-pessoal.md` now mentions it.

**Decisions:**

- Mark the wrong move's origin and destination squares, not the whole board — it shows exactly which move was wrong without hiding the position.
- New `--square-wrong` token (`#d4513f`) instead of reusing `--square-check` — the check color is orange and would not read as an error; like the other square tokens, it is the same in both themes because the board keeps its wood colors.
- Status text uses the existing `--danger` color — it is the shared error color and already adapts to the dark theme.

## 2. Number the board rows from the 1st rank

**Prompt:**

> Inverta a numeração das linhas da matriz do tabuleiro em play/rules.js para que a linha 0 seja a 1ª fileira e o peão branco ande com +1; ajuste o desenho do tabuleiro em game.js para continuar com as brancas embaixo.

**What was done:** In `play/rules.js`, row 0 of the board matrix is now the 1st rank: the position reader uses `rank - 1`, square names use `row + 1`, the white pawn moves with `row + 1` (two squares with `row + 2` from `WHITE_PAWN_START_ROW`, now 1). In `play/game.js`, `renderBoard` draws the rows from 7 down to 0 so White stays at the bottom, and the square color formula was flipped so a1 stays dark. Checked in Node: pawn, king and knight targets, square names and SAN come out as before.

**Decisions:**

- Row 0 is the 1st rank — the matrix index now grows in the same direction as the chess rank, so a white pawn moves forward with `+1`, which reads more naturally; the cost is drawing the rows backwards.
- Flip the square color test to `(row + column) % 2 === 0` for dark — with the new numbering a1 is row 0, column 0, and it must stay a dark square.
- The searches in `playOpponentReply` and `findCheckedKing` keep their 0-to-7 loops — they look for a piece, so the order of the rows does not matter.

## 3. Show "Próximo exercício" only after a solved attempt

**Prompt:**

> Na página do exercício (play/game.html), faça o botão "Próximo exercício" aparecer somente quando o usuário resolver o exercício; depois de um lance errado ele deve continuar escondido, assim como no último exercício da lista. Verifique se a função loadNextExercise é mesmo necessária para descobrir o próximo exercício e, se não for, remova-a.

**What was done:** In `play/game.js`, `endAttempt` now shows the "Próximo exercício" link only when the result is `"solved"` (and the list has a next exercise). The exercise id read from the address is turned into a number in `startPage`, so `loadNextExercise` can find it among the ids the API sends; before, the text id never matched and the link never got its address. The "Saving" item in `.docs/02-site-pessoal.md` now says when the link appears.

**Decisions:**

- Keep `loadNextExercise` — the order of the exercises lives in `lista_exercicio.ordem` and an exercise can be in more than one list, so the next exercise cannot be worked out from the id (such as `id + 1`, which would also jump into the next list after the last exercise); the page needs the list from `GET /exercicios/listar/:idLista/:idUsuario`.
- Keep the existing `<a class="btn">` link instead of a new `<button>` — it already looks like a button and it navigates to another page, which is what a link is for.
- Hide the link after a wrong move — only "Tentar de novo" is offered then, so the user retries the exercise before moving on.
