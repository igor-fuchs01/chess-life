# Prompts — 2026-11-01

## 1. Strong password validation on the front-end and back-end

**Prompt:**

> Eu quero que você adicione validações no back-end e front end de caracteres para senha forte, contendo no mínimo 8 caracteres, incluindo maiuscula, minuscula, caractere esepecial e numero. A mensagem de erro deve aparecer abaixo do botão de entrar(como já esta sendo feito) e não pode ser enviada para o backend antes do front valida-la primeiro

**What was done:** Added `public/auth/password.js` with `validatePasswordStrength`, used by `auth/signup.js` and `auth/login.js` before any request is sent; the error shows in the existing form message below the submit button. The API (`usuarioController.js`) repeats the same check on `POST /usuarios/cadastrar` and `POST /usuarios/autenticar` and replies `400` with the same messages. Updated RN02 and the docs (`01-project.md`, `02-site-pessoal.md`, `03-database.md`, `04-api.md`) and the sign-up password placeholder.

**Decisions:**

- RN02 now requires at least 8 characters with an uppercase letter (`A-Z`), a lowercase letter (`a-z`), a digit and a special character (anything other than `A-Z`, `a-z`, `0-9`) — requested by the user; ASCII classes keep the rule simple, so accented letters count as special characters.
- The check runs on login too, not only on sign-up — the user asked for the message below the "Entrar" button. Accounts created earlier with a weak password can no longer log in.
- One error message per missing requirement, checked in order — tells the user exactly what to fix.
- The front-end check lives in `auth/password.js`, shared by both auth pages, instead of being copied into each script — keeps the two pages' rules from drifting apart.
