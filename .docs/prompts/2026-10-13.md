# Prompts — 2026-10-13

## 1. Create CLAUDE.md and the prompt-logging skill

**Prompt:** 

> Crie um arquivo `CLAUDE.md` para o projeto e uma skill que registre, ao final de cada tarefa, o prompt enviado e as decisões tomadas. Guarde esses registros em uma pasta `.docs/`, organizados de forma que seja fácil consultar o que foi pedido em cada dia e quais decisões continuam valendo.

**What was done:** created `CLAUDE.md`, the skill `.claude/skills/registrar-prompts/SKILL.md` and the `.docs/` folder with `prompts/2026-10-13.md` (this file) and `decisoes.md`.

**Decisions:**

- One prompt file per day in `.docs/prompts/` — avoids a single file that grows without limit and makes it easy to find what was asked on each date.
- Lasting decisions also go to `.docs/decisoes.md` — lets the current state of the decisions be checked without rereading every prompt.
- The obligation to log lives in `CLAUDE.md`, which is loaded in every session, and the format lives in the skill — the skill alone would only be used when the model judged it relevant.
- No hook was set up to record prompts automatically — it was not requested; it remains an option if logging by instruction proves unreliable.
- Logs in Portuguese — the language the user writes in.

## 3. Commit skill and documentation in English

**Prompt:** 

> Crie uma skill de commits com as regras abaixo, para ser executada ao final de cada tarefa, e passe toda a documentação do projeto para inglês.
>
> * Toda mensagem de commit começa com um tipo (`feat`, `fix`, `chore`, `docs`, `refactor`…), sem escopo entre parênteses, seja qual for a mudança. Exemplo: `feat: stop sending answers left blank`.
> * Prefira commits pequenos: divida cada grupo de mudanças nas menores unidades com sentido (um componente, uma correção, uma configuração, um tópico de documentação), e garanta que cada commit funcione sozinho.
> * Nunca misture mudanças não relacionadas (por exemplo, uma funcionalidade nova e uma correção) no mesmo commit.
> * Nunca adicione linhas `Co-Authored-By` nas mensagens.
> * Nunca faça push sem autorização prévia.

**What was done:** created the `commit` skill in `.claude/skills/commit/SKILL.md` and added a "Commits" section pointing to it in `.claude/CLAUDE.md`. Translated the Portuguese parts of `.claude/CLAUDE.md`, this log, the decisions file and the logging skill into English. Renamed the skill `registrar-prompts` to `log-prompts` and `.docs/decisoes.md` to `.docs/decisions.md`. Nothing was committed.

**Decisions:**

- Commit messages start with a type and never carry a scope in parentheses; commits are small, never mix unrelated changes, carry no Co-Authored-By line and are not pushed without prior authorization — rules given by the user.
- The `commit` skill runs after any task that changed files — the user's rules open with "After finishing any task".
- `log-prompts` runs before `commit` — so the log entry of a task lands in that task's commits.
- All documentation is in English, but prompt quotes stay verbatim in the language they were written in — the log exists to record exactly what was asked.
- The skill and the decisions file were renamed to English names — the assistant's choice, to match the documentation and the "identifiers in English" convention in `CLAUDE.md`. Entries 1 and 2 keep the names the files had at the time.
- The `log-prompts` skill no longer describes the hooks flow — the hook script and `.claude/settings.json` are gone from the repository, so the skill went back to being the only logging mechanism.
- Nothing was committed in this turn — the request was to create the skill, and the pasted rules were taken as its content, not as an instruction to commit the existing work.
